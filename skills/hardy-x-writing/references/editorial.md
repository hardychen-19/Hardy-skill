# 编辑与审校

先诊断具体问题，再修订，最后润色。完整长文可分轮；简短修稿不必仪式化。保留用户重要判断，发现事实或逻辑错误则明确指出并给可支持的写法。

## 1. 事实与逻辑

检查数字、人物、产品、引用和第一人称经历的来源，尤其核对标题是否夸大、例子是否能支持结论、反例是否被忽略。外部原文的观点归其作者；补充的解释不要冒充原文。未核实就标注，不能用“自检通过”代替查证。

长文重复出现的术语保持一致；专业词首次出现按目标读者补必要解释。若分段写作，先统一术语、核心判断与例子，再合并全文检查衔接，不必默认并行调用子代理。

## 2. 读者理解与可用性

读者是否知道眼前对象是什么、为何需要下一步？同一案例是否能承接解释？教程有入口、动作、预期结果及检查方式吗？是否讲明必要权限、成本和适用边界？观点文章是否有清楚推理，而非只在最后要求行动？

缺少证据、操作步骤或关键解释先修内容，不用配图、加粗或小标题掩盖。

## 3. 节奏与人格

是否像一个有判断的人在讲清具体事情？哪里重复、突然换对象、需要回头才能理解？口头禅、惊叹、短句是否过多？有没有借来的职业经历、机械自嘲或强行升华？检查自然程度，不计口语词数量，不以模仿任何作者口癖作为通过条件。

按照 [自然表达与作者在场](natural-expression.md) 定位五种问题：空泛道理、推理跳步、取舍模糊、篇幅没有轻重、情绪没有来源。先修内容再修措辞。用户的判断有没有被润色成泛泛的两面话？追问后是否真正给了答案？概念后面有没有具体对象和后果？删除一句“更深刻”的总结，文章是否损失信息？已经说清楚的段落，不为统一文风再次重写。没有作者素材时不补假经历；保留必要问题等待用户回答。具体诊断与停止条件以该参考文件为准。

## 4. 标题与交付

标题在正文清楚后决定。用户要求候选时通常给3–5个，按材料选择问题、结果、解决方案、对照或共鸣方向，并包含一个直白标题。数字必须来自正文；结果标题不能把单例写成普遍保证；悬念不能隐去关键限制。

需要摘要时写出读者能得到什么，而非重复标题或写“本文介绍”。不要把摘要强行塞进正文开头。用户已经定标题时不自动重选。

排版最后进行，保持既有观点、事实、语气和段落顺序。标题服务真实转折；列表服务并列或步骤；表格服务对照；代码块保留可复制文本。不要重写正文来凑排版，不用大量加粗或引用块制造重点。

## 审校反馈

用户只要成稿时完成内部审查，最多说明影响定稿的未核实内容。用户要求审校时按“位置与问题 → 读者影响 → 修改建议”列出关键项，区分已修复和待补材料。没有实际检查的部分不能标通过。流程完成不等于成稿效果已经经过真实读者验证。
