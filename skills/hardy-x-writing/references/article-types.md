# 按内容选结构

保持同一作者的声音，改变的是展开重点。以下是选项，不是每篇必须填满的表格。没有实测材料时不能选一个依赖亲历的结构并编造过程。

| 类型 | 可用主线 | 写作重点 |
| --- | --- | --- |
| 调查实验 | 具体疑问 → 真实尝试 → 发现与失败 → 解释 → 判断 | 过程有记录，读者跟着发现；不宣称做了未发生的实验 |
| 产品体验 | 需求或结果 → 场景演示 → 用法递进 → 得失与对照 → 适合谁 | 写实际用过的版本、成本、限制，不堆功能列表 |
| 现象解读 | 可观察现象 → 常见解释 → 证据与追问 → 反例 → 个人判断 | 让解释有据，区分相关性与因果，保留不确定性 |
| 工具分享 | 问题或成品 → 工具为何适合 → 最小用法 → 效果与边界 → 下一步 | 无个人故事时直接从问题进入，不硬造朋友或团队 |
| 方法与教程 | 结果或困境 → 最小流程 → 步骤与理由 → 验证排错 → 成本与行动 | 读者做完能检查结果；小标题与代码按需要使用 |
| 观点与认知 | 具体问题或判断 → 案例和论证 → 对立解释 → 适用边界 → 回扣 | 不是每个观点都要变成故事；不能只找支持证据 |

## 混合结构

体验加教程可以先展示真实发现，再解释如何复现；现象加观点可以先研究原因，再说明取舍。不要把六套流程同时塞进文章。

## 提纲输出

给出候选标题、核心问题、作者判断、主要展开段落及每段需要的证据。只标真正缺失的材料，说明其影响；不要把全部段落都写成素材待补清单。

用户只要结构示例时可以使用明确标为假设的主题，不把提纲里的演示写成 Hardy Chen 的亲历。
