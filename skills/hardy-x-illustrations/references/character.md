# 从一张照片建立个人角色

## 角色优先级

1. 用户本次明确指定的角色或照片。新照片表示建立新版本，不静默覆盖旧图。
2. 用户已有可用个人档案。使用 Python 3.10+ 运行本技能的 `scripts/character_profile.py resolve`（脚本路径相对于本技能目录，不能假设当前工作目录就是安装目录），读取返回的角色图和身份说明；按本次主题调整表现方式。
3. 首次使用且没有档案：读取用户上传的一张单人清晰照片，用可用图像工具生成一张个人角色参考。只有文章、没有照片时，请用户上传一张照片；不自动使用作者 Hardy 的人物替代用户。

随包 [Hardy 角色图](../assets/hardy-ip-approved-v1.png)只用于用户明确要求的示例与画风演示，不是新用户身份。原始照片不能写入技能安装目录、公开仓库或发布包。

若当前环境没有 Python 或脚本不可执行，可按相同 profile.json 字段与校验规则保存个人档案并检查文件；不能因为缺少脚本而声称已成功保存。

## 首次照片初始化

先确认工具能读取照片并生成真实图片。只观察发型、眼镜、脸部轮廓等可见特征，不猜职业、民族、性格等身份。沿用照片可见衣着；未显示下装时采用无品牌的中性衣着，不声称还原真实穿搭。照片中多人或脸部无法辨认时，仅询问必要的选人或补图问题。

默认 `soft-3d` 柔和立体；用户已选择其他主题则使用相应 [主题规则](themes.md)。不要求用户自行提供提示词、风格文件或角色三视图。

```text
根据用户上传的单人照片，生成一个供正文配图反复使用的个人角色参考。
保留照片可见的发型、眼镜、脸部轮廓和衣着特征，不复制摄影背景和姿势。
画风采用选定主题。默认：软圆 Q 版、紧凑比例、柔和哑光立体，暖白留白、低饱和色。脸部是平滑软圆卡通面，头发是简洁块面发束，不画毛孔、逐根发丝或摄影皮肤；整体约三头身。
全身单人，面部与衣着容易识别，自然站立、手部可见，干净背景，无文字、无物件遮挡。
照片未展示的衣着使用简单中性补全；不推断个人身份，不增加商标。
只生成一张独立角色图，不把照片和角色拼成对照海报。
```

替换“选定主题”为本次主题的实际视觉规则；使用当前工具的参考图机制传入照片，并明确照片是身份参考。生成失败时说明缺少的能力，不把文本、旧图或空文件当角色产物。

打开生成结果，检查是否保留可见身份、手部与比例正常、符合主题。保存实际图片和一份短身份说明（发型、眼镜、脸型、衣着、比例），再调用 `scripts/character_profile.py save --reference <生成图片路径> --identity-notes <身份说明路径> --theme <主题ID>`。脚本复制生成角色与说明到个人配置区，记录校验值；返回的路径是后续配图身份来源。生成提示词保存到该角色目录，原始照片无需复制或长期保存。

首次结果默认 `ready`、`user_approved: false`，可以直接继续本次配图并在以后复用，无须额外确认。用户明确认可时才记录认可；以后要求修改外貌时新建角色版本，旧版本保留。只上传照片时交付个人角色和主题选择入口，不虚构文章；照片和文章一起提供时完成角色后继续文章任务。

## 复用与切换主题

后续不重复索要照片。每次调用先读档案并查看角色图，将该图作为身份参考：固定发型、眼镜、脸型、衣着和头身比例，动作按知识点变化。材质与线条由选定主题决定；切换手绘、水彩或深色科技时保留同一身份，允许改变绘制媒介，不要求它们仍是立体材质。切换主题通过 `set-theme --theme <ID>` 记录，不重写原始角色。若用户要新的主题角色参考，生成并保存新版本。

引用文件丢失或校验不符时报告具体路径，不能回退成 Hardy 示例人物。用户重新提供参考或修复文件后再继续需要人物的图。用户明确要求不加人物时可直接做无人物图，不强制初始化。

人物通常从画面宽度约 15%–20% 起排，知识对象占主位；这是构图起点，头身比例来自角色图。动作要参与解释，不连续照抄站姿、插兜或指点。截图、数据图和无需角色的关系图可以不加人物。
